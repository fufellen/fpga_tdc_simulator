# Имитатор ВЦП на ПЛИС (Gowin GW2A, по мотивам HPTDC)

ГУИ-имитатор время-цифрового преобразователя, реализованного целиком на
ПЛИС **GW2A-LV18PG256C8/I7**: визуализация процессов измерения и расчёт
параметров системы.

Модель — **построчный порт SystemVerilog-исходников**, а не независимая
математика. Эталон (read-only): `C:\workspace\verilog-fpga-tdc\src\TDC\fpga_tdc\`,
репозиторий `verilog`, ветка `fpga_tdc`, коммит `aadf5b89`, ModelSim 10.5b.

## Что показывает

| Вкладка | Содержание |
| --- | --- |
| **Измерение** | одно измерение СТАРТ→СТОП: такт, импульсы, фронты выборки; снимок линии задержки с термометрическим кодом; вся цепочка `C·T_clk − t_fine` до интервала и дальности |
| **Линия и калибровка** | профиль линии, гистограмма плотности кодов, DNL, INL, передаточная функция; построение калибровочной LUT и её применение в других вкладках |
| **Развёртка и статистика** | развёртка интервала (точный порт тестбенча) в трёх конфигурациях против золотых чисел ModelSim; Монте-Карло со случайной фазой и джиттером такта |
| **Параметры системы** | LSB, СКО, диапазон, дальность, мёртвое время, темп измерений; разрешение против числа отводов и диапазон против разрядности счётчика |

## Проверка соответствия эталону

Агрегаты развёртки совпадают с ModelSim 10.5b до последней цифры:

| конфигурация | макс \|ошибка\| | СКО | вердикт |
| --- | --- | --- | --- |
| A — идеальная линия | 34 пс | 17,3 пс | PASS |
| B — кривая линия, без калибровки | 192 пс | 73,3 пс | FAIL |
| C — кривая линия + калибровка | 57 пс | 20,4 пс | PASS |

Порт анализа плотности кодов из `fixtures/code_density.dat` воспроизводит
`fixtures/calibration.hex` **побайтно** (включая банковское округление
Python и наследование пустых кодов).

## Что именно портировано из RTL

Точность порта — не «похожие формулы», а воспроизведение разрядностей,
округлений и конвейерных сдвигов:

- **`delayline.py`** ← `tdc_delayline_model.sv`: транспортные задержки
  ячеек в целых пикосекундах; семантика выборки строгая — отвод виден
  высоким при `rise_arrival < T` и `fall_arrival >= T` (неблокирующее
  присваивание с задержкой применяется после чтения на фронте);
- **`channel.py`** ← `tdc_channel.sv`: 2-триггерный синхронизатор,
  детект `new_meas = nz2 & ~nz2_d`, захват `coarse` до инкремента,
  латентность `valid_o` = E+2; код 0 не детектируется, минимальный
  наблюдаемый код 1; повторное взведение требует полного стекания линии;
- **`calib.py`** ← `tdc_calib.sv`: LUT из `NTAP+1` значений по 20 бит,
  клэмп `fine_raw > NTAP`, семантика `$readmemh` (короткий файл
  оставляет хвост идеальным), формат `%05x`;
- **`top.py`** ← `tdc_top.sv`: `ts = coarse·TCLK_PS − fine_ps` со
  знаковым 32-битным усечением; конечный автомат спаривания
  `have_start`/`have_stop` вместе с его особенностью — старт, взведённый
  на том же такте, где выдаётся интервал, теряется (более позднее
  присваивание в блоке побеждает);
- **`density.py`** ← `analyze_inl_dnl.py`: порядок операций с
  плавающей точкой сохранён ради побайтного совпадения `calibration.hex`;
- **`sweep.py`** ← `tdc_top_tb.sv`: `dt = 800…53000` шаг 173 пс, фаза
  СТАРТа 1234 пс, импульс 7000 пс, порог 100 пс = 2 LSB.

## Что НЕ портировано (расширения модели)

Помечено в коде и в ГУИ, чтобы не выдавать за поведение железа:

- **джиттер такта** — в RTL-модели его нет, она детерминирована;
  в Монте-Карло добавляется гауссов сдвиг фронта;
- **случайная фаза в Монте-Карло** — свой ГСЧ, не `$random` ModelSim,
  поэтому гистограмма совпадает с RTL только статистически (для точного
  сравнения используется закоммиченная фикстура);
- **калькулятор параметров** — расчёт в плавающей точке по формулам из
  заметок, а не порт RTL;
- **потеря измерения** — тестбенч после сторожевого таймера прочитал бы
  устаревшее значение; модель явно сообщает, что интервала не было.

## Границы достоверности

- Развёртка сверена с ModelSim **только по агрегатам** (макс/СКО/PASS):
  повекторный дамп 302 точек в RTL-репозитории не сохранён.
- Поведение при импульсе короче периода такта в RTL не тестировалось;
  модель воспроизводит физику бегущей полосы честно, но золотых данных
  для этого режима нет.
- Переполнение 16-битного грубого счётчика RTL не обрабатывает; модель
  воспроизводит модульную арифметику, золотого вектора нет.
- Режим multi-phase (`tdc_fine_line_multiphase.sv`) не инстанцирован в
  RTL и присутствует здесь только как расчётная альтернатива в
  калькуляторе.
