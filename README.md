# Имитатор ВЦП на ПЛИС (Gowin GW2A, по мотивам HPTDC)

> **Инструкция пользователя — [docs/manual.md](docs/manual.md).** Этот
> файл про устройство проекта и его верификацию; как пользоваться
> программой, что означает каждый регулятор и график — там.

ГУИ-имитатор время-цифрового преобразователя, реализованного целиком на
ПЛИС **GW2A-LV18PG256C8/I7**: визуализация процессов измерения и расчёт
параметров системы.

Модель — **построчный порт SystemVerilog-исходников**, а не независимая
математика. Эталон (read-only): `C:\workspace\verilog-fpga-tdc\src\TDC\fpga_tdc\`,
репозиторий `verilog`, ветка `fpga_tdc`, коммит `aadf5b89`, ModelSim 10.5b.

## Что показывает

| Вкладка | Содержание |
| --- | --- |
| **Измерение** | одно измерение СТАРТ→СТОП: такт, импульсы, фронты выборки; снимок линии задержки с термометрическим кодом; вся цепочка `C·T_clk − t_fine` до интервала и дальности |
| **Линия и калибровка** | профиль линии, гистограмма плотности кодов, DNL, INL, передаточная функция; построение калибровочной LUT и её применение в других вкладках |
| **Развёртка и статистика** | развёртка интервала (точный порт тестбенча) в трёх конфигурациях против золотых чисел ModelSim; Монте-Карло со случайной фазой и джиттером такта |
| **Ширина и multi-hit** | измерение ширины импульса штатной коммутацией ВЦП и предлагаемое расширение с буфером отметок на канал |
| **Аналоговый вход** | форма эха, пороговый дискриминатор с time-walk, CFD, цифровая поправка по ширине; сверка с прогоном LTspice |
| **Параметры системы** | LSB, СКО, диапазон, дальность, мёртвое время, темп измерений; разрешение против числа отводов и диапазон против разрядности счётчика |

## Проверка соответствия эталону

**Повекторно.** Все 302 точки развёртки из настоящей RTL-симуляции
(`fixtures/modelsim_sweep_*.csv`) воспроизводятся точно: интервал, оба
сырых тонких кода и разность грубых счётчиков — расхождений ноль во всех
трёх конфигурациях. Дампы сняты `rtl_bridge/tdc_dump_tb.sv` — тем же
стимулом, что в эталонном тестбенче, плюс запись CSV; сам RTL не менялся.

**По агрегатам** (то, что печатает эталонный тестбенч):

| конфигурация | макс \|ошибка\| | СКО | вердикт |
| --- | --- | --- | --- |
| A — идеальная линия | 34 пс | 17,3 пс | PASS |
| B — кривая линия, без калибровки | 192 пс | 73,3 пс | FAIL |
| C — кривая линия + калибровка | 57 пс | 20,4 пс | PASS |

**Побайтно.** Порт анализа плотности кодов из `fixtures/code_density.dat`
воспроизводит `fixtures/calibration.hex` бит в бит, включая банковское
округление Python и наследование пустых кодов.

**Против LTspice.** Модель аналогового входа независимо считает схему из
`analog/tdc_frontend.cir` и сходится с пакетным прогоном LTspice XVII в
пределах 0,1 пс: пороговый дискриминатор 4203,2 / 2720,6 / 2066,4 пс на
амплитудах 0,25 / 0,5 / 1,0, CFD — 4556,9 пс на всех трёх.

## Сборка EXE

```bash
powershell -ExecutionPolicy Bypass -File scripts/build_exe.ps1
```

Готовый файл — `dist\FPGA_TDC_Simulator.exe` (в git не хранится). Скрипт
создаёт `.venv`, ставит закреплённый набор из `requirements-exe.txt`,
прогоняет `scripts/check.py`, собирает однофайловый пакет во временном
каталоге (чтобы синхронизация Google Drive и антивирус не мешали чистке
`build/`), затем публикует его в `dist/` и прогоняет дымовой тест —
запускает собранный EXE из нейтрального рабочего каталога и проверяет,
что он создал снимок экрана. Золотые фикстуры упакованы внутрь, так что
вкладка калибровки работает и без репозитория.

Если канонический EXE занят запущенным экземпляром, скрипт сам закроет
процессы **строго по совпадению полного пути** (сначала штатное закрытие
окна, потом принудительное) и опубликует новую сборку на место старой.
Флаги: `-SkipTests`, `-SkipSmokeTest`, `-PythonCommand "путь"`.

## Что именно портировано из RTL

Точность порта — не «похожие формулы», а воспроизведение разрядностей,
округлений и конвейерных сдвигов:

- **`delayline.py`** ← `tdc_delayline_model.sv`: транспортные задержки
  ячеек в целых пикосекундах; семантика выборки строгая — отвод виден
  высоким при `rise_arrival < T` и `fall_arrival >= T` (неблокирующее
  присваивание с задержкой применяется после чтения на фронте);
- **`channel.py`** ← `tdc_channel.sv`: 2-триггерный синхронизатор,
  детект `new_meas = nz2 & ~nz2_d`, захват `coarse` до инкремента,
  латентность `valid_o` = E+2; код 0 не детектируется, минимальный
  наблюдаемый код 1; повторное взведение требует полного стекания линии;
- **`calib.py`** ← `tdc_calib.sv`: LUT из `NTAP+1` значений по 20 бит,
  клэмп `fine_raw > NTAP`, семантика `$readmemh` (короткий файл
  оставляет хвост идеальным), формат `%05x`;
- **`top.py`** ← `tdc_top.sv`: `ts = coarse·TCLK_PS − fine_ps` со
  знаковым 32-битным усечением; конечный автомат спаривания
  `have_start`/`have_stop` вместе с его особенностью — старт, взведённый
  на том же такте, где выдаётся интервал, теряется (более позднее
  присваивание в блоке побеждает);
- **`density.py`** ← `analyze_inl_dnl.py`: порядок операций с
  плавающей точкой сохранён ради побайтного совпадения `calibration.hex`;
- **`sweep.py`** ← `tdc_top_tb.sv`: `dt = 800…53000` шаг 173 пс, фаза
  СТАРТа 1234 пс, импульс 7000 пс, порог 100 пс = 2 LSB.

## Что НЕ портировано (расширения модели)

Помечено в коде и в ГУИ, чтобы не выдавать за поведение железа:

- **multi-hit** (`multihit.py`) — в RTL такого нет вовсе: реализация
  однохитовая, автомат спаривания сбрасывает оба флага сразу после
  выдачи интервала. Модель буфера отметок нужна, чтобы оценить цену
  расширения до того, как писать RTL; с ModelSim не сверялась;
- **джиттер такта** — в RTL-модели его нет, она детерминирована;
  в Монте-Карло добавляется гауссов сдвиг фронта;
- **случайная фаза в Монте-Карло** — свой ГСЧ, не `$random` ModelSim,
  поэтому гистограмма совпадает с RTL только статистически (для точного
  сравнения используется закоммиченная фикстура);
- **аналоговый вход** (`frontend.py`) — независимый численный расчёт
  схемы, а не порт LTspice; сверен с её прогоном;
- **калькулятор параметров** — расчёт в плавающей точке по формулам из
  заметок, а не порт RTL;
- **потеря измерения** — тестбенч после сторожевого таймера прочитал бы
  устаревшее значение; модель явно сообщает, что интервала не было.

Измерение **ширины импульса** к расширениям не относится: это штатная
коммутация того же `tdc_top` (эхо на СТАРТ, инвертированное — на СТОП),
правок RTL она не требует.

## Границы достоверности

- Импульс короче периода такта в RTL не тестировался. Модель честно
  воспроизводит бегущую полосу и показывает деградацию на вкладке
  ширины, но золотых данных для этого режима нет.
- Переполнение 16-битного грубого счётчика RTL не обрабатывает; модель
  воспроизводит модульную арифметику, золотого вектора нет.
- Режим multi-phase (`tdc_fine_line_multiphase.sv`) не инстанцирован в
  RTL и присутствует здесь только как расчётная альтернатива в
  калькуляторе.
- Форма эха в аналоговой модели — та же, что в netlist; при реальном
  насыщении фотоприёмника форма меняется с амплитудой, и остаточный
  walk у CFD возвращается. Это в модели не заложено.
- Таблица walk-поправки строится по модели, а не измеряется на плате;
  её остаточная ошибка оценивается на промежуточных амплитудах, а не на
  тех же точках, по которым построена.

## Структура

```
src/fpga_tdc_sim/      модель (чистый stdlib, без Qt)
  params delayline channel calib top density sweep      — порт RTL
  multihit frontend syscalc                             — расширения
  cli fixtures
src/fpga_tdc_sim/gui/  Qt-слой (PySide6 + pyqtgraph)
  app launcher widgets
  timing_tab line_tab sweep_tab modes_tab frontend_tab calc_tab
fixtures/              золотые артефакты: гистограмма, LUT, дампы развёртки
rtl_bridge/            дамп-тестбенч поверх read-only RTL (+incdir)
tests/                 unittest, GUI-тесты пропускаются без PySide6
scripts/               check.py, make_screenshots.py, run_rtl_dump.ps1,
                       build_exe.ps1
```

Пересъём дампов из ModelSim (нужен установленный ModelSim ASE):

```bash
powershell -ExecutionPolicy Bypass -File scripts/run_rtl_dump.ps1
```
